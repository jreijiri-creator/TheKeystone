# Abacus.AI — Version 1.2 Changes

**Date:** September 11, 2026

## Summary

Fixed 5 issues reported by the user after first use of the Templater templates. Addressed Templater showing multiple options per template, missing facilitator name in closings, missing company tag, unclear AI action steps workflow, and no end-of-session guidance.

---

## Issue 1 & 3 Fixed: Duplicate Template Options + PDF Files

**Problem:** Templater was showing 3 options for each template (Session Note, OPFMS, Client Summary) instead of 1. The `.pdf` and `.docx` auto-generated versions of the templates were sitting inside `00-Templates/` and appearing as selectable options.

**Also clarified:** The PDF/DOCX files in `00-Templates/` were auto-generated by the Abacus.AI platform whenever markdown files were written — they serve no purpose in the vault and should not be committed.

**Fix:**
- Deleted all 6 auto-generated files from `00-Templates/`:
  - `Session-Note.pdf`, `Session-Note.docx`
  - `OPFMS-Client-Master.pdf`, `OPFMS-Client-Master.docx`
  - `Client-Summary-Email.pdf`, `Client-Summary-Email.docx`
- Added `.gitignore` at vault root to permanently block these from being committed again:
  ```
  00-Templates/*.pdf
  00-Templates/*.docx
  ```

---

## Issue 2 Fixed: Facilitator Name & Company Tag

**Problem:** Session Note and Client Summary closings showed `[Your Name]` as a literal placeholder. Also, no company tag was being auto-added to notes.

**Fix — Facilitator Name:**
- Added `const facilitator = await tp.system.prompt("Facilitator Name", "");` to both `Session-Note.md` and `Client-Summary-Email.md` header blocks
- Replaced `[Your Name]` with `<% facilitator %>` in the closing of both templates
- The OPFMS template already had the facilitator prompt — no change needed there

**Fix — Company Tag:**
- Added `the-keystone-group` as a hardcoded tag in all three templates' YAML frontmatter:
  - `Session-Note.md`: `tags: [session, <% slug %>, the-keystone-group]`
  - `OPFMS-Client-Master.md`: `tags: [client, EPL12, <% slug %>, the-keystone-group]`
  - `Client-Summary-Email.md`: `tags: [summary, <% slug %>, the-keystone-group]`

---

## Issue 4 Fixed: AI-Derived Action Steps Workflow

**Problem:** User was unclear whether pasting the transcript automatically extracted action steps or whether manual action was needed.

**Clarification:** This is a **fully manual process** — there is no automation. Obsidian cannot send text to an AI automatically.

**Fix:** Rewrote the section header in `Session-Note.md` with a clear numbered workflow:
1. Download Zoom/Fathom transcript
2. Paste excerpt into the note
3. Copy transcript + AI instruction → paste into Abacus.AI / Claude / ChatGPT
4. Instruction: *"Extract ONLY concrete action steps or commitments. List as bullets."*
5. Paste AI response back into Extracted Action Steps
6. Reminder: do NOT send transcript to client — extracted steps only

---

## Issue 5 Fixed: End-of-Session Workflow

**Problem:** User was unsure what to do after finishing writing a session note.

**Fix:** Added `## ✅ End-of-Session Checklist` section at the bottom of `Session-Note.md` (after the client summary draft). It contains 9 checkboxes in order:

1. Intangible scores filled in
2. Goals section complete
3. PFS score filled in + recorded in OPFMS
4. Assignment Selector checked
5. AI Action Steps extracted
6. Client Summary Draft finalized
7. OPFMS Tangible Tracking updated
8. Client Summary sent to client
9. GitHub Sync pushed
